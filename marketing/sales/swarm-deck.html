Thirteen agents, one architect, and a product that fought back

An AI agent swarm run with the discipline of a review board — what it found in 48 hours on a live product, how it is organised, and the things I have learned not to trust it with.

01 · What it found

In 48 hours, on a product that was already live

Four findings, stated flat. Each is written up with a file and a line number, and the repository is available on request.

Anyone who signed up first with the owner's published email became the administrator

A database trigger granted admin on account creation and never checked whether the address had been confirmed. The address is hardcoded in a public repository. Full owner console: read every account, reset any password, delete any account. The project's own handover notes instructed turning email confirmation off to unblock sign-ups — doing so would have made it a one-step takeover.

backend-review.md · C1 · fixed in migration 20260825090000

Private advertiser rates and contacts were readable by anyone

The migration revoked writes on the table and never revoked reads, and row-level security is row-scoped, not column-scoped. Confirmed by issuing the request with the public key that ships in the browser bundle: 200 OK, nine rows. The same missing grant had also silently broken the owner console's save — one mistake producing two opposite symptoms, and no audit had caught the second.

security-privacy-review.md · PR-2 · verified against production

The core screen was inventing its own content

An uncited hand-written table decided which piece of structure each species “is most likely to be working”, and where a species was missing from that table the code returned the first item in an array. Seven of the product's 104 recipes resolved that way, printed to the reader as an instruction — on a product whose entire commercial claim is that its content was researched rather than guessed.

qa-review.md · C1 · all 104 enumerated, 7 identified by name

The app bricked itself offline

An account gate wrapped every content route. Install it, drive to the water, lose signal, and the product was a sign-in form that could not be completed — with the entire guide already cached on the device. It also gated the safety pages, which the code itself marks NEVER GATE THIS.

02 · The specimen

The product is the proof, not the pitch

Shorebound is a researched, offline-first shore-fishing guide for a stretch of Florida's Gulf coast. It is live, with a database, four serverless functions, twelve migrations and a revenue plan. Small enough to audit completely; real enough that the findings cost something.

It is the specimen. It is not what I am selling. Everything after this is method, and the method is what transfers.

03 · Orchestration

One architect, specialists in parallel, a human at the gate

Reviewers are read-only by design. They find problems and write them up; they do not fix them. Nothing reaches production without a person.

The discipline is in the brief, not the tooling

Every agent is handed the same four things before it runs: the product's hard constraints, the record of mistakes already made, an explicit instruction to cite file and line, and a stated boundary on what it may not touch. Reviewers are told they may not fix. That is what turns fifteen chat sessions into a review board.

04 · The roster

Thirteen agents, and what each actually did

Role, function, and evidence. Every agent below did real work on this product. Two further agents exist that have never executed; they are described in the limits section rather than given a card here.

architectran
Role
The hub, and the highest-context seat. Decides what gets built and why; explicitly told to stay out of implementation it can delegate.
Function
Reads brief, roadmap and past mistakes before proposing. Produces system design and a scoped task breakdown, then delegates. May not pick a vendor from memory.
Did
Whole-system review against five hard constraints. Six critical findings — including the offline gate, and that the twenty-shop directory (the only revenue line) filtered through a live network read, so an advertiser bought exposure that vanished when the reader lost signal.
backend-engineerran
Role
Implements what the architect specs; does not redesign it. Flags a spec that does not survive contact with the code.
Function
Schema, migrations, row-level security, serverless functions. Audits authorization at every entry point.
Did
Found both production vulnerabilities — the unconfirmed-email admin grant and the readable advertiser rates — by reading twelve migrations in timestamp order and asking who could call what.
security-privacy-reviewerran
Role
Verifies the product's own trust commitments are true in code, not just in marketing. Standing gate before any launch milestone.
Function
Organises findings against NIST CSF 2.0 rather than an ad-hoc bug list, so gaps are visible and prioritised.
Did
Two reports. A NO-GO verdict for store submission, with the advertiser-data exposure confirmed against production. Then a supply-chain audit of a third-party package I had installed — byte-verifying what actually executed, and finding a path-traversal write in it.
qa-reviewerran
Role
Read-only. Finds problems and unverified claims; never fixes them. Verifies every claim another agent makes rather than accepting it.
Function
Runs the build and the suite itself. Hunts specifically for tests that would pass if the feature were deleted.
Did
Found the invented content in the core screen, enumerated all 104 recipes and named the seven resolving by array index. Also found the identification photographs were remote hotlinks excluded from the offline cache.
test-engineerran
Role
Makes regressions impossible to ship silently. Concentrates coverage where breakage costs most, not where testing is easiest.
Function
Maps the untested surface and ranks gaps by what breaking would actually cost.
Did
Found the entire live-data parsing layer had zero tests — 533 lines including timezone handling across daylight-saving boundaries — behind a suite of 316 passing tests.
documentation-writerran
Role
Keeps documentation from drifting behind the build.
Function
Marks every factual claim CONFIRMED or DRIFTED against the repository.
Did
Disproved two numbers the product was selling itself on. “20 verified businesses” was 9 verified of 20; “159 cited sources” could not be reproduced by any counting method. It also reported that it had no shell that session and said which checks it therefore could not run.
project-managerran
Role
Guards scope and reports honest status. It says no to good ideas.
Function
Re-measures rather than carrying numbers forward; every metric carries a verified flag and the method used.
Did
Established that “fixed” and “shipped” are different claims. Seven fixes were reported done; it queried the live database directly and found two had never been applied. Also built the launch tracker, generated from data so a stale number has nowhere to hide.
ui-designran
Role
The visual work — layout, typography, illustration. Verifies its own output in a real browser at real viewport sizes before reporting.
Function
Designs in a live design surface, not in prose. Screenshots before it claims.
Did
Eight design files — a 16-slide deck, a duplex one-pager, a three-sheet sales proposal, a welcome page at desktop and phone, alternative first screens, and three distinct interface directions for comparison. It preserved two deliberate blanks it was told not to fill.
infra-cost-strategistran
Role
Keeps running costs proportionate to revenue. Researches and recommends; never signs anything.
Function
Costs options at realistic scale and checks commercial terms before price — a cheap vendor that cannot legally support the use case is not an option.
Did
Commissioned by the architect to settle a basemap question. Found the map was both dated and unlicensed for commercial use, and that the free-forever option was also the only one satisfying the offline requirement.
marketing-creativeran
Role
Content production under a binding claims policy. Drafts only; never publishes without approval.
Function
Distinguishes the product's own voice, which may be rewritten, from researched content, which may only be quoted.
Did
Found the owner's spoken tone-direction had been pasted in as finished copy — including a maintainer's work order rendering under every species photograph in production. It refused to touch safety text and reported it instead.
ui-designerran
Role
Interface implementation — screens, components, flows.
Function
Reviews at real viewport sizes and measures rather than eyeballs.
Did
Reviewed the whole app for flow and intuitiveness, driving a real browser. Five of its eight critical findings were invisible in the source — including raw exception text rendering on the flagship screen, and a signed-out navigation where ten links did nothing at all.
naming-brand-researcherran
Role
Naming, domain availability, preliminary collision screening.
Function
Never lets a name reach external material without an honest account of what has and has not been screened.
Did
Killed three previously-favoured names with live collision testing, and settled the product's name. Ran in an earlier session, before the swarm was formally registered.
product-marketingran
Role
Positioning and copy accountable to actual build state rather than roadmap intentions.
Function
Every claim traced to something checkable.
Did
Wrote this document. It refused to attribute a finding whose author the repository does not record, flagged two authorship claims rather than asserting them, and declined to claim novelty for the method after checking the field.
05 · Disagreement

Convergence is evidence. Contradiction is the interesting part.

Three lanes, one finding, no coordination

The architecture, security and QA reviews each arrived by different routes at the same fact: production deploys through a path where none of the checks execute. Three independent confirmations is a stronger signal than one confident report.

Three reviews were wrong about the same thing

All three cited a test as proof that image licensing was handled. Later work proved that test cannot catch the problem at all — it only examines images that already declare a licence, so an unlicensed one is invisible to it. Seventeen had no licence recorded.

The fix was itself defective

Opening the app to offline readers was right, but the check was live — so the moment one bar of signal returned, the reader was thrown back to a sign-in form mid-page. Caught and corrected the same day, with the reasoning written into the file rather than only the commit.

And a person decides

Every report ends with the calls only a human can make. The account gate was flagged as a decision about the sign-up funnel, not an engineering one, and deliberately left open.

06 · Limits

What I have learned not to trust it with

This is the section I would want to read if I were hiring someone to do this.

  • Two agents exist that this document does not list. Neither has ever executed, so neither earned a card — including the unattended one, designed to work with nobody watching. Its safety rules are written and untested, so it does not go near a client repository.
  • One agent's declared tools do not exist. Its definition names three interfaces the server does not expose, and its own file admits the names are “illustrative”. It reviews well; it has never built.
  • A migration was built and then reverted. A correctly-licensed vector basemap replaced an unlicensed one. It compiled, passed 346 tests, put every marker in the right geography — and the map never drew. Parked with the code preserved and the diagnosis written down, rather than shipped or deleted.
  • An agent worked without a tool it needed and said so, naming the checks it therefore could not run. That sentence is worth more than a clean report.
  • Agents inherit assumptions from wherever they came from. This swarm was copied from a different product. Eight definitions still carried that product's domain reasoning, phrased as instruction — a marketing agent advising on real-estate aggregation, a test agent hunting duplicate property listings. The first commit on this branch strips it back out.
  • Reviewers are confidently wrong in packs. See the licensing test above. Independent review reduces that risk; it does not remove it, and nothing replaces checking the thing yourself.
07 · Transfer

What this looks like at your company

Multi-agent review is not novel in 2026 and I will not claim it is. The differentiation is in the briefs, the constraints and the verification — which is the part that does not come out of the box.

  • Parallel independent review, not a chain. Specialists that cannot see each other's findings before filing their own.
  • Every finding cites a file and a line, so the report is checkable rather than persuasive.
  • Reviewers may not fix. The agent that finds a problem does not get to grade its own repair.
  • Constraints are handed over, not discovered. Each brief carries the hard rules and the mistakes already made, so nobody rediscovers them expensively.
  • Escalation paths out of the system. Legal, licensing and adversarial testing questions get routed to humans by name, not answered by an agent with a confident tone.
  • A fix in the working tree is not a fix in production until it has been checked against the running system. That rule came from a real finding here and generalises to any team.
